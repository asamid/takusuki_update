## Preservation and recovery observations

The test used SHA-256 baselines for `.config/default.yml`, `operator-note.txt`, and
`files/upload-marker.txt`. All failure, rollback, patched success, and Vanilla success checks
kept those values unchanged, except for the deliberate isolated database-name switch between
the patched and Vanilla test databases. The Vanilla baseline was re-hashed after that deliberate
switch.

Rollback now accepts both successful histories and failed/incomplete histories. It still refuses
source-only rollback when the live migration ledger differs from the saved pre-update ledger.
The first cold 2026.10.0 startup took about 70 seconds, so the bounded readiness controls were
made configurable; the default remains 30 attempts at two-second intervals.

## Scope of compatibility evidence

Successful patch application, build, migration, service startup, and health checks establish that
this exact isolated 2026.10.1 path worked. They do not prove every application feature on every
future official tag. The updater therefore records the target as unverified when it differs from
the bundle reference, while retaining fail-closed runtime gates.

Patch 010 is limited to FederationChart. Patch 030 is the separate Note search/timeline blocked-host
query optimization: literal domains use DNS-suffix equality and wildcard rules retain `ILIKE`.
Neither the updater nor this release reclassifies 010 as the Note query optimization.
